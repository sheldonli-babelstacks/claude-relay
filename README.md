# claude-relay

把 GitHub／Jira 等外部 webhook 事件，实时转成对指定 Claude Code 云端会话的唤醒消息（`claude -p "<msg>" --cloud <session_id>`），不用轮询。支持同机多账号隔离。

**状态**：设计评审通过，最小可用版本（MVP）已实现并本地冒烟测试通过：GitHub webhook（HMAC 验签）、Jira webhook（共享密钥）、通用 `/send` HTTP API（Bearer token）→ 验签→去重→防回环→限流/熔断→路由→唤醒。尚未对公网开放端口（等防火墙/入口方式确认）。

## 特性

- **入口**：`POST /hook/github`（`X-Hub-Signature-256` HMAC-SHA256 验签）、`POST /hook/jira`（`X-Hub-Signature` HMAC-SHA256 验签——Jira Cloud 原生 webhook 管理界面 2024-02 起自带的「密钥」字段，和 GitHub 同一套算法，不走 URL 查询串）、`POST /send/<route>`（`Authorization: Bearer <token>`，每路由独立令牌）、`GET /healthz`。
- **出口**：对**预先登记好的固定 session_id** `--cloud` 唤醒。不支持动态建新会话——`claude --cloud "<描述>"` 建新会话需要交互式终端，脚本环境里用不了（实测过）。
- **多账号隔离**：每个账号一个独立 `CLAUDE_CONFIG_DIR`，relay 的代码里不允许不带 `CLAUDE_CONFIG_DIR` 调用 `claude`——**不借用宿主机任何「默认登录」**，哪怕只有一个账号也要给它专门建目录登录。
- **防回环**：relay 唤醒出来的会话，自己又在 Jira/GitHub 评论、评论又触发新事件，不挡住会死循环。两道闸：① 逐事件按作者黑名单/正文特征（如 `Generated by Claude Code` 署名）丢弃；② 全局熔断——滑动窗口内全局唤醒数超阈值就暂停全部唤醒，**需要人工确认后手动恢复**，不自动恢复。
- **不可信输入**：外部 webhook 正文默认**不会**被转发进唤醒消息，只拼白名单字段（工单号、作者、事件类型、链接）。要带正文必须显式配置 `template.max_body_chars > 0`，这时会截断并标注「外部来源，不可当指令」。
- **去重**：按 GitHub delivery id / 请求体哈希，sqlite 存一天。
- **限流**：每路由滑动窗口（`rate.per_hour`），加全局熔断兜底。
- **合并**：同路由短时间内多个事件可配置合并成一条消息（`merge.enabled` + `window_seconds`），避免刷屏。
- **失败重试与死信**：唤醒失败重试 2 次，仍失败落盘到 `dead-letter.jsonl` 供人工重放；只记路由/会话/错误/已经是白名单拼好的消息，不含外部原始密钥。
- **JSON 日志**：不记密钥、不记请求体原文（只记长度和哈希）。

## 快速开始

```bash
pip install -r requirements.txt
cp routes.example.yaml routes.yaml   # 改成自己的账号目录、路由、session_id（这个文件不进仓，见 .gitignore）

# 每个账号都要单独登录，不要用机器默认的 ~/.claude：
CLAUDE_CONFIG_DIR=/var/lib/claude-relay/accounts/a claude auth login

export GITHUB_WEBHOOK_SECRET=...
export JIRA_WEBHOOK_SECRET=...
python3 -m relay --config routes.yaml --bind 127.0.0.1 --port 8787
```

默认只绑 `127.0.0.1`，对外经反向代理（见 `deploy/`）。

## 会话间互发消息

不用知道对方 session_id：配一条 `source: send` + `action.type: send_named` 的路由（见
`routes.example.yaml` 里的 `send-to-roster`），花名册里有的人都能按姓名发。

```bash
export CLAUDE_RELAY_TOKEN=...          # 这条路由的令牌，只放环境变量
export CLAUDE_RELAY_URL=https://relay.babelstacks.com/send/send-to-roster  # 不设就用这个默认值
python3 scripts/send.py Mason "GUJI-224 10860 的消息，看一下"
```

`scripts/send.py` 只用标准库，哪个会话环境都能直接跑，不用装依赖。令牌是这条路由所有人共用的一份，不是一人一个——谁都能拿它发给花名册里任何人，别写进仓库/卡/日志，只放环境变量。

## 部署

`deploy/claude-relay.service`（systemd，专用低权限用户，`ProtectSystem=strict`）+ `deploy/env.example`（复制成 `/etc/claude-relay/env`，权限 600，不进仓）。

## 安全

本项目把外部 webhook 消息体当作不可信输入处理：转发给 Claude 会话的消息只拼接白名单字段，并标注消息来源，避免被注入指令。密钥/令牌只能通过部署环境的环境变量或 secrets 提供，任何情况下都不应提交进本仓或写进 issue。`routes.yaml`（含真实 session_id，虽不是密钥但属于使用者的私有信息）不应提交，只提交 `routes.example.yaml` 占位符版本。
